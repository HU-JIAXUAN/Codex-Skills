# DSP 实时数据链与工具链

本参考用于把算法接入真实固件、定位错拍与吞吐问题，或验证优化是否有效。按当前问题读取相关小节；修改一个滤波系数不要求重查整套启动链。

先复用工程已有的构建、采样、缓冲和测量设施。算法公式、数值误差、构建结果与板上时序分别提供证据，不能相互替代。

## 1. 从实际构建配置识别执行环境

先读取本次使用的目标和编译/链接命令，再判断源码会怎样执行；IDE 中选中的工程名称和文件夹名称只作线索。

| 检查对象 | 要取得的证据 | 发现不一致时的动作 |
|---|---|---|
| 构建目标与源码集合 | 当前配置、实际编译文件、预定义宏、优化与调试选项 | 先确认目标选对、源码纳入构建，再解释结果 |
| 编译器与 ABI | 版本、目标核选项、数据模型、浮点和调用约定 | 核对库兼容性与跨单元接口，不能只比较源代码类型名 |
| SDK、头文件和库 | 展开后的 include 路径、库搜索路径、实际链接文件 | 把头、库与设备支持文件配对到所需版本 |
| 链接和运行库 | 链接脚本、map、数学/格式化函数实际实现 | 检查软件回退、额外依赖、内存增长与运行位置 |
| 生成配置与手工源 | 生成入口及受维护的配置文件 | 从源配置修复，不修改生成 makefile 或厂商头掩盖路径错误 |

缺头文件时，先看展开路径和文件是否存在；宏展开为空、混入另一 SDK 或目标目录错误，与文件缺失是不同原因。

更换工具链、ABI、库或优化选项后，针对受影响目标重建，并保存实际命令、map 和诊断。只有本次变化会影响其他配置时才扩大构建范围。

## 2. 追踪采样到结果生效的事件链

先画出本次问题涉及的一条真实链路；每个箭头标明事件来源、数据有效条件、执行单元与等待条件：

```text
时钟与分频
  → 定时/外部触发
  → 采样或接口锁存
  → 转换/传输完成，结果可读
  → DMA、ISR、任务或加速器消费
  → 算法计算完成
  → 输出发布/提交
  → 硬件或下游消费者生效
```

- 核对实际时钟源、分频、计数模式、触发点和事件分频；不从 ISR 名称或单个频率宏推断采样率。
- 区分采样开始、保持结束、转换完成、传输完成与结果可读；提前触发只代表计算可启动，不代表结果已有效。
- 启动时先完成代码/数据和缓冲初始化，再清残留状态、配置完成通知，最后开放事件源；停止、复位和重新启动应有对应顺序。
- 读反馈时记录本次样本序号或时间戳、有效性、最后有效值和数据年龄；复用旧值必须可识别。
- 核对生产与消费节拍。异步传感器不必每次计算都产生新帧，但新鲜度上限、丢帧和超时行为必须明确。
- 双缓冲或跨周期处理要说明“本次计算消费哪一拍、输出在哪一拍生效”，不能只比较变量最终值。

分别记录原始采样率、算法实际更新率、抽取/分块后的有效数据率与遥测输出率。做频谱时使用该序列的真实时间基准，不能直接套 PWM、ISR 或串口发送频率。

遥测抽取、丢包或不均匀发送会改变可分析的数据序列；保留采样序号/时间戳，先确认均匀性与缺口，再判断谐波、混叠或滤波效果。

## 3. 明确缓冲所有权与状态生命周期

对 DMA、ISR、线程和加速器共享的数据，至少说清下表；单执行上下文的纯算法无需引入多余同步机制。

| 契约项 | 必须可回答的问题 |
|---|---|
| 写入与读取 owner | 哪个执行单元可写，谁消费，是否允许并发 |
| 缓冲区布局 | 长度的单位、对齐、步长、通道交织方式、有效元素数 |
| 发布条件 | payload、有效长度与状态何时构成完整快照 |
| 有效期与复用 | 消费者完成前是否会被覆盖，何时归还或切换缓冲 |
| 序号与积压 | 如何检测重复、跳号、pending、溢出和积压 |
| 错误路径 | busy、超时、丢帧或结果无效时谁恢复、输出什么 |
| 生命周期 | 初始化、启动、停止、复位和参数更新分别允许在哪个上下文执行 |

共享状态不能仅靠 `volatile` 保证原子性、顺序或一致性。根据目标内存模型与访问宽度选用短临界区、原子操作、消息、双缓冲或有证据的快照协议。

存在 cache、非一致性 DMA 或多个地址视图时，再核对可访问区域、cache 维护和内存屏障；不能把某个系列的“无需 cache 维护”套给全部 DSP。

发布时先完成数据和元信息，再按同步协议通知消费者；消费者确认后才复用缓冲。异构核共享结构体时，另核对 ABI、地址含义和字段布局，不直接传递未经约定的原生指针。

滤波器、FFT 工作区和累加状态由明确的实例拥有；区分参数初始化与运行状态复位。多个通道或任务不得无意共享可变状态。

更新系数、增益或长度时，明确何时切换、是否复位或变换状态、如何避免半更新；需要平滑切换时按算法要求设计，不能依赖写入碰巧发生在空闲期。

## 4. 用截止时间组织实时预算

先确定下游真正要求的完成时刻：下一帧覆盖前、输出寄存器装载前、消费者读取前，或系统规定的响应期限。周期相同不代表可用窗口相同。

至少区分以下部分，并说明哪些可重叠、哪些必须串行等待：

| 预算项 | 应观察的内容 |
|---|---|
| 数据准备 | 采样/传输何时结束，结果何时可读 |
| 启动等待 | 中断屏蔽、任务排队、优先级阻塞与加速器忙 |
| 计算 | 实际算法路径、边界分支、库调用与状态更新 |
| 访存与同步 | 等待状态、总线争用、cache 行为、DMA 与共享内存访问 |
| 提交与生效 | 数据发布、硬件装载点、后续消费者或传输等待 |

吞吐量、端到端延迟、抖动与截止时间余量分别评价。缩短内核计算不一定缩短结果生效延迟，加速器与 CPU 并行也不代表加速器内部任务并行。

测量记录包含目标频率、构建配置、代码/数据位置、输入工况、竞争负载、采集方法和观测开销。覆盖能改变路径的极值、错误处理、并发和内存状态。

报告实测最大值时写清覆盖条件；它不自动等于已证明的 WCET 上界。未测目标最坏时间时写 `NOT_MEASURED`，不能用主机运行时间、理论指令数或平均 cycle 填充。

发现 overrun、pending、溢出或样本序号跳变时，先定位发生在哪一段，再决定调整算法、调度或采集节拍；不能只增大队列隐藏持续超载。

## 5. 控制观测带来的扰动

- 实时路径只做有界记录，使用项目已有的非阻塞发布接口；格式化、长串口等待和调试器交互放到允许的上下文。
- 非阻塞发送必须定义 busy 时的行为：丢弃、合并、覆盖或有界队列，并记录丢失情况；不得无限重试或无限增长缓存。
- 异步发送前说明缓冲区何时可修改。DMA 尚未读完时复用数据，会让观测值与算法状态错配。
- 估算记录量与输出带宽，核对格式化栈、共享缓冲、运行库和锁的成本；不要根据某个精简 printf 库的宣传数字作预算。
- 用周期计数器、计时外设、trace 或 GPIO 等现有设施时，量化开销与分辨率，说明包围的是内核、完整 ISR 还是事件链的一段。
- 比较观测开启和关闭的行为，注明断点、单步、CIO/semihosting 或 halt 会改变哪些外设和时序。

## 6. 检查链接、装载和冷启动差异

当错误仅出现在 Flash、脱离调试器或更换执行单元后，先查 map 与启动流程：

1. 确认代码、常量、状态、栈与工作区的实际段及运行位置；检查容量、对齐、重叠和访问权限。
2. 有 LOAD/RUN 分离时，核对装载源、运行目的、复制长度的单位与执行时机；不能以“符号存在”替代复制完成。
3. 确认可变数据、常量、共享 RAM 和系数何时初始化；初始化或清零可能覆盖此前写入的值。
4. 检查执行单元取得内存所有权之前，谁负责复制与初始化；取得所有权之后，原执行单元是否仍能合法访问。
5. 区分调试器装载、运行到 main、软复位、独立启动与断电重启；识别调试脚本额外完成的时钟、RAM 或外设设置。
6. 使用已授权的目标验证方式复核相关路径；只有 map 或构建证据时，明确尚未证明冷启动与板上行为。

调试工具显示的大端/小端、word 视图或导出布局不直接证明目标存储与协议字节序。用已知位型核对地址单位、显示设置和导出文件，再解析参数或原始数据。

## 7. 依据测量优化

1. 固定当前算法意图、输入范围、误差容限、输出时间语义与可复现基线。
2. 通过目标 profile、map 或反汇编定位热点，区分计算、库回退、访存、同步和观测瓶颈。
3. 一次改变一个主要因素：数据布局、库实现、数值格式、内存放置、编译选项或执行单元。
4. 优先复用工程已验证的内核与库；采用 intrinsic、SIMD 或加速器前核对对齐、长度、别名、状态与数值限制。
5. 用相同向量和可比构建条件检查误差、饱和、状态推进、输出顺序与时延，再测目标性能和资源变化。
6. 性能收益成立且契约保持时保留修改；不能复现的加速效果标为假设，保留回退点。

编译器选项或快速数学实现可能改变运算顺序、异常值处理和误差；“生成了目标指令”只证明选择了实现路径，不能代替输出与时序验收。

## 8. 按证据报告结果

| 证据 | 可以说明 | 仍需单独确认 |
|---|---|---|
| 公式分析与主机仿真 | 既定模型、输入和数值语义下的行为 | 目标 ABI、外设与真实执行时间 |
| 目标编译/链接/map | 纳入目标的代码可构建，布局与符号可核对 | 实际初始化、数据新鲜度和硬件行为 |
| 目标结果比对与运行观测 | 所测路径的数值、时序和资源情况 | 未覆盖工况、冷启动或故障恢复 |
| 指定负载下的时间测量 | 已说明条件下的延迟、抖动和实测最大值 | 更强 WCET 上界或全工况声明 |

结尾只报告与当前问题有关的目标、命令、输入/工况、结果和未验证项。计划命令标为 `NOT RUN`；未测时间标为 `NOT_MEASURED`。

## 来源与适用边界

- 官方系列实例：[TI 优化指南的存储器章节](https://software-dl.ti.com/C2000/docs/optimization_guide/phase3/memory.html)用于核读代码/数据放置与访存影响；[CLA 软件开发 FAQ](https://software-dl.ti.com/C2000/docs/cla_software_dev_guide/faq.html)用于核读异构执行、数据共享和调试限制。具体能力以目标系列、编译器及版本为准，不从实例推广固定延迟或吞吐数字。
- 本地笔记《C28x CPU》《C2000 DSP基本数据类型》启发目标 byte、ABI 与工具单位核对；类型图缺少版本上下文，不能当作全部工具链的类型定义。
- 《控制律加速器 CLA》《F28388D CLA》启发触发链、内存所有权、任务积压与初始化顺序；无 frontmatter 的内容只作经验线索，任务数量等实例细节不进入通用规则。
- 《CCS安装多版本C2000Ware编译报hw_memmap.h丢失问题》为 `apply/draft`，用于提炼展开路径、头库配对和构建证据；单次编译成功不推广为板级验证。
- 《C2000 FOE Upload》为 `capture/draft`，用于识别快照、发布握手和长度单位问题；本参考不沿用其中依赖编译端的长度表达式或原生结构体线格式。
- 《ccs printf重定向》《读取Flash参数》启发观测成本与工具显示边界；示例中的无界格式化、阻塞发送及显示字节序推断不作为规范。以上笔记仅在本次维护中只读提炼，运行时不依赖个人笔记库。
