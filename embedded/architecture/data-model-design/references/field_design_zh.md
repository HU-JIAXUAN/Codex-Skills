# 字段归属与强类型组合

重点是每个字段有明确语义、维护者和寿命，不是让所有对象拥有相同布局。一个私有结构体也可以边界清楚；配置、状态和数据共用存储外壳本身不是错误，越权访问和含糊语义才需要处理。

以下问题与例子用于支持选择：先判断在当前业务中是否适用，再决定表示与机制。没有必要把所有设备都补成示例的字段集合。

## 公共身份与具体内部模型分开

身份与统一管理通常比具体数据表示更稳定。选择公共部分时，判断它是否真是共同语义，而不是把温湿度、运动、电池、显示等对象的差异堆入基类。

共用槽位、内嵌成员或 `void *` 各有代价。需要类型擦除时，将转换限制在实际类型与寿命明确的边界内；粗分类或函数表非空不能代替具体 API/参数契约。

## 配置与状态怎样划分

- `cfg` 说明对象按什么约定工作：绑定哪条总线、什么地址、参数或默认周期等。板级绑定、产品策略与算法参数仍按变化原因归属，不因统称配置就混进一个全局头文件。
- `ctx` 保存对象怎样推进工作的私有状态，例如 busy、错误计数、转换阶段、上次尝试时间。由所属模块的初始化、行为或回调按约定维护，不给其他模块任意写权限。
- 生命周期状态、硬件初始化完成、业务运行模式、数据有效性可能不同；含义相同时避免副本，各有独立含义时明确关系。例如尝试采样时间与最近成功采样时间不应含糊地都叫 last_sample。
- 运行复位只重置约定状态；有效校准与参数按配置策略保留。允许在线更新的配置定义校验、生效边界和并发方式，不通过强转去修改真正只读的对象。

## 内嵌、指针与共享按实际选择

常见组合是公共 base 加强类型 `cfg/ctx/data/ops`：配置和只读操作表由指针绑定，小型私有上下文与结果内嵌在每实例对象内。它便于静态分配，也不强制这一表示；较大上下文、DMA 缓冲、外部内存或已有对象可采用指针，但需说明分配者、对齐、借用和释放责任。

配置只有内容、生效规则和存储寿命都适合共享时才能共用。同型号设备也可能位于不同总线、地址，拥有不同校准与采样策略；可共享公共参数、分别绑定实例资源，或直接使用各实例配置。每实例可变 ctx/结果保持隔离，除非明确设计了共享所有者与同步协议。

`const T *` 限制通过该指针修改 T，不保证底层对象没有其他可写别名；`T * const` 固定指针本身，不使 T 只读。`const` 不自动保证 ROM/Flash 驻留、线程安全或数据新鲜；实际存储位置看目标工具链、链接段与 map，指针引用也必须覆盖使用期。共享只读函数表不保存实例状态，状态从实例参数取得。

## 对外数据需要什么语义

`data` 可以是输入、结果或受控视图，并非所有字段都必须对外开放。对外数据至少能说明数值意义与必要有效条件：

| 示例 | 需要明确的解释 |
|---|---|
| 温度 | 有符号、范围和缩放；若单位为 0.001 °C，则 -1250 表示 -1.250 °C |
| 湿度 | 若 `humidity_milli_pct` 表示百分数乘 1000，则 50.123% 为 50123、100% 为 100000；不能只用含糊的“千分比”描述 |
| 时间戳/序号 | 时间源、单位、采样还是发布时间、过期阈值与计数回绕；valid 不代表仍然新鲜 |
| 输出设备当前值 | 区分请求目标、已提交值与实际测量反馈；写入 LED 亮度不自动证明物理亮度已被测得 |

采集失败时可以保留最后有效结果，但要让使用者知道其年龄、质量或最新错误，不能给旧数据续写新采样时间伪装新鲜。失败后输出不变、失效或带错误保留旧值，由接口选择并说明；读者需要一致结果时，发布机制应避免把半更新数据当作完整结果。

只读指针不会冻结底层数据，`volatile` 不能代替多字段快照同步。根据任务/ISR/回调关系选择短临界区复制、双缓冲所有权或其他适合目标的发布协议，明确唯一写入方、读者获得的一致版本、指针有效期和缓冲区复用条件。不同字段/缓冲若有不同 owner，需明确交接而不是暗中多写。

## 行为接口与结果分离

`ops` 保存行为而非当前结果。实例参数指明配置、状态与结果归属；签名应保留真实类型，不把参数不同的函数强转成一张通用表。获取已有快照、发起硬件采集、推进状态机是不同语义；`read()` 可以按项目约定表示其中一种，但应明确阻塞性、完成时点和输出有效期，不让查询动作隐式触发慢速 I/O。

两个传感器可以实现同一测量能力，但函数签名相似还不够；需核对实例类型、单位/坐标、错误、上下文、时序与结果寿命。若各驱动依赖不同具体对象，使用小适配连接稳定能力接口，不靠强转不同上下文凑互换。

## 名称与实际语义

Zephyr 的 `config/api/data` 展示配置、行为与每实例运行维护数据的分离；其中 `data` 不是这里专指的对外测量快照。不要仅按字段同名映射概念，也不把一种 Service 预留槽位推广成所有设备的基类。

## 核对依据

- [Zephyr 官方 Device Driver Model](https://docs.zephyrproject.org/latest/kernel/drivers/index.html)：配置、每实例运行数据和分类 API 的职责。
- [WG14 N1570 §6.7.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：const 限定与只读存储的区别；不将 C11 新语法变成 C99 要求。
