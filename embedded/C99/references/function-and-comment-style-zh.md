# 函数设计与统一注释体系

这是当前自研新代码的默认基线：先设计能被调用者理解的输入/输出，再以一致的普通中文块注释表达，最后核对代码、头文件、模板、formatter 和 lint 是否一致。项目既有明确约定或用户本次要求优先；第三方/生成代码保持自己的风格。

## 函数设计先确定什么

| 部分 | 必须能明确回答的问题 |
|---|---|
| 用途 | 一个主要可观察动作是什么，谁调用，为什么需要此接口 |
| 输入 | 每个参数的含义、单位/范围、可空性；对象是否已经初始化，缓冲区长度是什么 |
| 输出 | 返回值、输出参数、实例状态和硬件各发生什么变化；何时有效 |
| 失败 | 错误怎样区分；输出/状态保持、清空还是部分更新；调用者下一步可以做什么 |
| 寿命 | 指针借用还是保留，谁释放/复用，输出数据活到什么时候，是否允许别名 |
| 上下文 | 是否阻塞、可重入，允许 ISR/任务/循环哪种入口，共享访问由谁保护 |

参数顺序保持“实例/上下文、输入、输出”，缓冲区与长度/容量相邻。不修改的输入指针用 `const`，但 `const` 不代替生命周期和并发说明。输出参数只在约定的成功条件下有效；有不同失败策略时明确说明，不从模板自动假定。

公共接口在头文件提供完整使用合同；`.c` 的定义说明关键实现意图，复用头文件合同，不把整段参数说明重复成第二个容易漂移的版本。私有简单纯计算函数可用一句清楚的说明；复杂或有隐藏副作用的私有函数同样补齐必要合同。

## 统一外观

- 普通说明使用 `/* ... */`，简体中文，句末默认无句号，不加 Doxygen 标签，不给每行加装饰 `*`。
- 多行块采用独占的 `/*`、同级内容缩进 4 空格、独占的 `*/`；代码上方注释与其前面的代码空一行，保持与所说明代码同级缩进。
- 文件用途、函数说明、字段和局部意图采用同一套中文词汇，单位与接口一致。不要一个头文件写 A、实现改成 mA、遥测又按标幺解释。
- 分区可使用统一的一行星号标题，内容为职责，如“内部声明”“对外接口”；不是每个函数都插入装饰线，也不混用多套分割样式。
- 函数体 4 空格缩进；函数左括号独行，控制块左括号同行；类型 `PascalCase`、函数 `snake_case`、参数/局部 `lowerCamelCase`。有现成公共符号时保持兼容性。
- 不生成作者/公司/工号/日期/版本/历史占位符，不虚构 MISRA、功能安全或测试认证。确有项目文件头要求时填真实信息。

## 文件注释

文件头说明用途和职责边界。必要时补资源/调用条件和关联头文件，不抄目录名或逐函数列表。

```c
/*
    用途：维护容量游标，为调用者预留连续区域
    职责边界：只计算偏移，不分配或访问实际缓冲区，不提供并发同步
    相关文件：cursor_example.h 定义使用合同
*/
```

`.h` 文件重点说明公开能力、单位和使用前提；`.c` 重点说明实现边界与需要维护者注意的约束。是否需要文件名、许可证、真实作者等元数据服从当前工程，不套用空历史表。

## 函数注释

有参数/失败/状态变化的公共接口使用以下结构，仅保留适用且有内容的行：

```c
/*
    预留连续区域并返回起始偏移
    输入：cursor 为已初始化游标；count 为预留字节数，允许为0
    输出：startOffset 接收预留前偏移；失败时输出和游标都保持原值
    返回：CURSOR_OK成功；其余结果表示参数、状态或剩余容量错误
    约束：startOffset不能指向cursor内部；同一游标由调用者串行访问
*/
CursorResult cursor_reserve(Cursor *cursor, size_t count, size_t *startOffset);
```

“输入/输出/返回/约束”是稳定的说明词汇，不是凑数量的空标签。无参数的 `void` 简单函数不必写“输入无、输出无、返回无”；一个字段就是结果的纯查询也不必硬改成错误枚举+输出指针。存在可空指针、失败、单位、生命周期或上下文限制时必须说明，不能以函数简单为由略去。

公共声明的每个参数应能从输入/输出说明定位到，返回结果逐类解释，不能只写“成功/失败”而不说明如何识别。参数 `ctx` 是上下文而非天然输出；自动检查不能仅凭非 const 指针推断输出语义。

## 函数内关键代码注释

说明维护者从代码本身不容易看出的原因、边界和顺序，紧邻相应代码块：

```c
/* 先用剩余容量比较，避免position与count相加发生size_t回绕 */
if (count > cursor->capacity - cursor->position) {
    return CURSOR_NO_SPACE;
}

/* 所有检查通过后再更新，保证失败路径不会推进游标或覆盖输出 */
*startOffset = cursor->position;
cursor->position += count;
```

需要说明的典型位置：长度/范围判定的原因、单位转换与缩放、算法近似前提、状态提交点、资源取得与回退、重试/等待上界、特殊寄存器访问顺序、同步/缓冲区发布。复杂函数可按逻辑阶段分段；阶段编号按需使用，不能与实现顺序漂移。

不逐行翻译 `i++`、明显的空指针 guard 或赋值。纯装饰星号、重复函数名、照抄条件表达式不算关键意图说明；“原子操作”“安全处理”等词也不能代替当前代码到底保证了什么。

## 字段、枚举与整体一致性

字段说明用途、单位/范围和谁维护；配置由用户填写，运行状态由模块维护，结果何时有效要区分。枚举逐项解释具体状态/错误，函数的返回说明与枚举含义一致。必要时给数值例子，但不机械给每个标量造例子。

统一从现有模板或本 Skill 的[完整头文件](../assets/cursor_example.h)、[完整实现](../assets/cursor_example.c)起步。示例演示合同和注释，不要求业务工程引入同名类型或容量游标框架。

## 检查与人工复核

机器可检查部分格式、命名、非空说明、参数名覆盖及配置启用的关键意图注释存在性；缺少说明应报告明确位置。机器不能因为出现“输入”“输出”就认定信息正确。

人工或模型复核必须确认：单位/范围与计算一致，错误覆盖全部失败路径，输出更新时机与注释一致，指针寿命和并发前提真实，关键注释解释了原因而非制造噪声。详情见[验证与 Hook](verification-and-hooks-zh.md)。
