# 表达式、宏与控制流

## 触发语境

运算优先级、整数提升、符号转换、溢出、移位、宏、`sizeof`、`inline`、条件分支、循环、`switch` 或求值顺序问题使用本页。
任务是理解或修复行为时先确定预期结果；不能从题目给出的某个编译器输出反推语言保证。
本页由已加载的 C99 总入口按需使用，不为单个运算符或关键字再次注册独立 Skill。

## 必要输入

- 操作数的实际类型、合法范围、单位，以及中间结果可能达到的范围。
- 所有副作用、函数调用和宏展开；分支或循环要保持的不变量、结束条件及失败动作。
- 目标编译器、整数表示、优化选项，以及调用点对运行时间或重入性的限制。

## 设计方法

1. 写清计算或状态转移目标，再选择表达式；一条语句只承载读者能直接看出的副作用。
2. 推导整型提升和通常算术转换后的类型，先处理负值、范围与缩窄，再决定是否转换。
3. 在运算发生前检查溢出条件；长度用减法界定剩余容量，乘法先处理零并检查除法边界。
4. 将依赖执行顺序的读写拆成独立语句；函数实参之间不能依赖 C99 未规定的求值顺序。
5. 让正常路径和失败路径都明确退出；对等待、重试和解析循环给出上界与超限动作。
6. 用真实状态设计 `switch`，明确非法状态和有意贯穿；关键注释解释为何贯穿或为何终止。
7. 只有表达形式确有收益时才用宏；能以函数表达的计算优先使用有类型检查的函数。

针对常见机制进一步处理：

- 先理解短路逻辑，再使用 `&&`、`||` 守护访问；不要混淆按位运算与逻辑运算。
- 宏参数和整体表达式适当加括号，多语句宏用 `do { ... } while (0)`；这仍不消除重复求值。
- 会多次求值的宏不得接收递增、赋值或有副作用调用；需要时改为函数或适合的 `static inline`。
- `inline` 不保证机器码内联；头文件定义与外部定义须符合目标采用的 C99 链接规则。
- `sizeof(array)` 与参数退化后的指针不同；变长数组相关操作可能求值，不能笼统认定没有副作用。
- 移位先核对提升后位宽、符号和移位量；无符号掩码也不能假定 `1U` 在每个目标上都有 32 位。

## 注意事项与限制

- 有符号溢出是未定义行为；无符号回绕有定义，但计数、时间比较和容量计算仍须满足业务语义。
- 强转发生在错误运算之后不能修复已发生的溢出；不要用强转把有效告警压下去。
- 不给 `f(x++, x++)` 一类未定义行为安排“正确输出”，先向真实需求落实明确的执行顺序。
- 括号解决分组阅读问题，不能解决对象寿命、求值顺序、重叠复制或类型别名问题。
- 不为了减少行数使用复杂三元表达式，也不为满足行数指标将连续算法机械切碎。
- 实时等待和寄存器读写的语义使用实时指南；表达式简洁不表示时序正确。

## 实际验证

用目标告警和相称静态分析复核转换、副作用、移位与控制路径；必要时查看预处理输出和汇编。
复用边界测试验证零值、负值、最大合法值、刚超界、循环上限和非法状态；算术边界测试不得主动执行 UB。
host sanitizer 可补充发现问题，不能证明所有输入正确；目标执行时间和中断可用性仍需实际测量。
仅对可逆的排版或注释调整不新造测试；改变计算或退出行为时使用能区分前后行为的用例。
