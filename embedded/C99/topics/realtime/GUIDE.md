# 实时、并发与硬件访问

## 触发语境

ISR、任务、主循环、`volatile`、中断、临界区、锁、原子访问、DMA、cache、寄存器、轮询或执行时间问题使用本页。
先沿实际调用链确定运行上下文，函数名含 `isr` 或变量带 `volatile` 都不能替代证据。
架构边界、平台适配或解耦必须调用架构入口；处理器、OS 和外设细节再按需加载对应专项。

## 必要输入

- 入口调用链、抢占关系、核与总线参与者、周期、截止时间及允许阻塞范围。
- 每个共享对象的所有者、写入者、读者、访问宽度、发布顺序和缓冲区复用时机。
- 目标手册中的寄存器副作用、原子指令、屏障、cache 和 DMA 一致性要求，以及现有原语。

## 设计方法

1. 区分控制、数据采集、处理和发布的真实时间点，确定本次操作必须满足的截止时间。
2. 查清调用链是否可能等待、日志阻塞、分配、递归或调用不可重入库；不能只看当前函数体。
3. 为共享数据选择项目已有的所有权转移、快照、队列、临界区或目标原子机制。
4. 说明数据、时间戳、长度和质量位如何形成一次一致发布；读取方何时可以消费或丢弃。
5. 给 DMA/异步传输安排缓冲区借用起止、完成状态和失败恢复，完成前不得复用仍被访问的存储。
6. 对轮询、重试和等待设可验证上界及超时动作；把无界恢复移出硬实时路径。
7. 根据手册确定寄存器读写宽度与顺序，核对读清、写 1 清零、保留位和读改写副作用。
8. 在关键代码旁解释顺序、屏障或延后的原因，函数合同写明可调用上下文和阻塞限制。

按当前对象作出明确选择：

- `volatile` 仅用于需要其语言访问语义的对象；同步、原子性与一致快照另外证明。
- 单核关中断只覆盖相应抢占者；DMA、其他核、cache 和外设写缓冲仍按目标机制处理。
- 多字段快照不能由单个字段读取原子性推导；读者需要一致版本或受保护的发布过程。
- 寄存器 W1C 状态按手册写入，不能机械使用 `|=`；位域布局也不能跨编译器假定。
- C99 不直接提供 C11 `_Atomic`；使用项目批准的目标原语时明确扩展范围和编译证据。

## 注意事项与限制

- 不用变量命名、正则或注释标签推断 ISR 安全、锁正确、无竞争或寄存器语义。
- `const` 不保证内存放置，`volatile` 不保证多核顺序；软件屏障和硬件屏障各有适用边界。
- host stub 只能证明该替代路径；删掉真实 DMA、cache 或抢占不会得到目标并发证明。
- 平均耗时不证明最坏耗时；一次示波器截图也不覆盖所有优先级、异常和负载组合。
- 不为小改动制造新调度层；优先使用已验证的目标机制并限制本次影响范围。

## 实际验证

用目标构建和必要的反汇编核对原语、访问宽度、屏障及库调用；map 用于放置与资源证据。
用板级测量检查最坏相关路径的执行时间、中断延迟、采样窗口和超时动作，记录触发及负载条件。
通过有针对性的抢占、DMA 延迟、通信失败或超时场景复核发布与恢复；host 测试保留其适用范围。
未执行的硬件与时序验证单独列出，不将 Lint、编译或主机测试通过描述为实时验收通过。
