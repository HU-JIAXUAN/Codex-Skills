# 数据类型、变量与生命周期

## 触发语境

类型选择、整型宽度、结构体字段、状态存储、全局变量、初始化、指针寿命、`const`、`static`、`extern`、`typedef` 或协议布局问题使用本指南。
先判断要表达的数据和生命周期，再匹配词语；已加载 C99 入口时直接补读本页。
涉及模块职责、平台适配或解耦时必须同时使用架构入口；本页只处理 C 表示和访问合同。

## 必要输入

- 每项数据的含义、单位、合法范围、精度、无效状态和更新时机。
- 创建者、唯一或多个写入者、读者、释放者，以及对象、缓冲区和回调的存活区间。
- 目标整数与地址宽度、`CHAR_BIT`、对齐、字节序、ABI，以及协议规定的外部表示。

## 设计方法

1. 先列出真实值域和状态转移，再选择类型；“通常够用”不能代替上下界推导。
2. 数量、容量和索引优先考虑适合对象大小的类型；有符号物理量保留符号，转换前处理负值和缩窄。
3. 区分配置、运行状态、结果和诊断数据；只保留需要存储的事实，派生值说明计算或缓存失效条件。
4. 把每个可变对象的所有者、写入路径和生命周期落实到接口；借用指针注明是否可空、可写和可保留。
5. 选择最小必要的作用域与链接；本文件私有对象优先 `static`，跨文件声明来自正式头文件。
6. 明确初始化成功、部分失败、复位、停止和销毁的边界；复位运行状态不应顺便覆盖用户配置。
7. 将单位、有效条件和生命周期写在字段或函数合同附近，复用统一中文块注释外观。

按具体问题补充：

- `struct` 表达一起成立的数据；不为了统一外观堆入不相关状态，也不把所有标量机械拆成对象。
- `enum` 表达有限状态或取值集合；枚举大小和底层表示不能直接作为线协议或持久化 ABI。
- `union` 必须记录当前有效成员及切换规则；不把读取其他成员当成通用类型转换办法。
- `typedef` 用于有稳定含义的类型；避免隐藏所有权或指针层数，使接口看不出借用与可变性。
- `const` 限制通过该访问路径修改对象；不能证明没有可写别名、对象位于 Flash 或内容永不变化。
- 自动对象离开生命周期后不可继续借用；异步传输、排队回调和延后清理要单独核对。

## 边界与限制

- 不假定 `char` 为 8 bit、`int` 或 `long` 为 32 bit；标准中的字节与协议 octet 要明确区分。
- `uint32_t` 等精确宽度类型与 `uintptr_t` 并非所有实现必有；不能用固定宽度整数普遍保存指针。
- 协议按字段位宽、字节序和长度编码；native struct、padding、bit-field 或 `packed` 不能替代协议定义。
- 不通过不兼容指针类型访问对象；对齐正确和大小相同也不能单独证明访问合法。
- `memset(..., 0, ...)` 不普遍等同于合法初始化指针、浮点或硬件状态；按类型和目标约定初始化。
- ISR/任务/DMA 共享状态转到实时指南；加 `volatile` 不会补齐原子性和快照一致性。

## 实际验证

核对初始化、使用和销毁调用链，覆盖失败回退、重复初始化、停止后访问及借用结束边界。
用实际目标构建、map 和必要的布局检查确认宽度、对齐、放置与接口链接；host 布局只证明 host。
协议编码/解码使用已知字节序样本和边界长度复核；涉及并发的有效性还需真实调度或板级证据。
类型和字段命名检查只提供形式证据，不能证明单位、所有权和数据有效性描述正确。
