# 嵌入式架构模式目录

本文件只定义模式及其选择条件。模式不能覆盖[依赖规则与门禁](dependency_rules_and_gates_zh.md)，也不能替代对变化轴和成本的分析。

## 结构与边界模式

<a id="PAT-001"></a>
### PAT-001 分层架构（Layered Architecture）

- 意图：按语义稳定度和技术职责组织代码，使高层策略不直接接触低层机制。
- 适用：系统已出现应用、服务、设备和平台等不同变化速率。
- 避免：仅创建目录，不限制 include、链接和类型可见性。
- 成本：需要明确每层公共面，并持续检查越层依赖。

<a id="PAT-002"></a>
### PAT-002 端口与适配器（Ports and Adapters）

- 意图：由核心侧定义所需能力的 Port，环境侧用 Adapter 接入硬件、OS 或供应商库。
- 适用：同一策略需要主机测试、跨平台或替换设备实现。
- 避免：把底层 API 原样包一层后称为 Port。
- 成本：增加契约、映射和组合工作。

<a id="PAT-003"></a>
### PAT-003 适配器（Adapter）

- 意图：在两个已有接口之间转换调用、数据和错误语义。
- 适用：第三方接口不可改，或旧接口需要接入新契约。
- 避免：适配器同时承担策略决策与状态编排。
- 成本：需要维护双侧语义映射和兼容性测试。

<a id="PAT-004"></a>
### PAT-004 外观（Facade）

- 意图：为复杂子系统提供小而稳定的入口，隐藏初始化顺序和内部协作。
- 适用：调用者只需要少量用例，而子系统内部接口很多。
- 避免：把所有系统能力塞入一个万能入口。
- 成本：外观容易膨胀，需要按用例控制公共面。

<a id="PAT-005"></a>
### PAT-005 策略（Strategy）

- 意图：把可替换算法放在同一契约下，由外部选择策略。
- 适用：存在真实算法变体，且调用流程相同。
- 避免：只有一个实现、没有测试替身或变化证据时预建接口。
- 成本：多一次间接调用和策略生命周期管理。

<a id="PAT-006"></a>
### PAT-006 依赖注入（Dependency Injection）

- 意图：由外部提供依赖，使模块不负责查找或创建具体实现。
- 适用：需要替换驱动、时钟、存储、日志或测试替身。
- 避免：隐藏在可变全局变量中的“注入”。
- 成本：构造参数与生命周期关系需要显式维护。

<a id="PAT-007"></a>
### PAT-007 组合根（Composition Root）

- 意图：在单一位置选择实现、构造实例、连接依赖并启动生命周期。
- 适用：系统存在多个 Adapter、策略或产品配置。
- 避免：让每个模块在初始化函数里自行查找依赖。
- 成本：组合点会了解较多具体类型，必须保持只组装、不承载业务。

<a id="PAT-008"></a>
### PAT-008 注册表（Registry）

- 意图：按 ID、名称或能力集合保存已存在对象，并提供受控查询。
- 适用：对象集合在启动时注册，运行期按键选择或枚举。
- 避免：把注册表当作无限制的 Service Locator；使用者不应知道所有具体对象。
- 成本：要处理键冲突、容量、注册阶段和查找失败。

<a id="PAT-009"></a>
### PAT-009 工厂方法（Factory Method）

- 意图：把“一类对象创建哪个具体实例”的决定封装到创建接口。
- 适用：创建逻辑随产品、资源或运行配置变化，且调用者不应知道具体类型。
- 避免：只返回一个静态对象却引入复杂工厂层次。
- 成本：需要定义创建失败、内存来源和对象销毁语义。

<a id="PAT-010"></a>
### PAT-010 抽象工厂（Abstract Factory）

- 意图：一次创建彼此兼容的一族对象。
- 适用：板卡、芯片或产品变体要求整组驱动/服务一致切换。
- 避免：各对象可独立变化时强行绑成一族。
- 成本：产品组合数量增加，工厂契约也更稳定、更难修改。

<a id="PAT-011"></a>
### PAT-011 桥接（Bridge）

- 意图：让高层抽象与底层实现沿两个维度独立变化。
- 适用：例如“设备语义”和“通信承载”都有多个独立变体。
- 避免：只有单一变化轴时增加双层抽象。
- 成本：对象关系更多，调试路径更长。

<a id="PAT-021"></a>
### PAT-021 表驱动资源配置（Table-driven Resource Configuration）

- 意图：把任务、外设、队列、引脚等实例集合写成静态配置表，由统一创建循环消费。
- 适用：资源集合固定、字段同构、需要集中审阅栈深/优先级/容量预算。
- 避免：把产品策略、条件分支和初始化顺序依赖塞进表项。
- 成本：表结构变更影响所有条目；缺失项容易被误认为已实现，需要配合 [DR-016](dependency_rules_and_gates_zh.md#DR-016)。

## 行为与执行模式

<a id="PAT-012"></a>
### PAT-012 表驱动状态机（Table-driven FSM）

- 意图：显式表达状态、事件、迁移和 Enter/Run/Exit 行为。
- 适用：生命周期、协议、故障恢复或 UI 流程具有有限状态。
- 避免：把状态分散在多个布尔变量和隐含调用顺序中。
- 成本：需定义非法事件、超时、迁移可观测性和测试矩阵。

<a id="PAT-013"></a>
### PAT-013 生产者—消费者（Producer–Consumer）

- 意图：用有界队列或环形缓冲区隔离采集与处理速率。
- 适用：ISR 到线程、通信接收与解析、日志生成与落盘。
- 避免：没有背压、溢出和所有权策略的裸共享缓冲区。
- 成本：引入容量、延迟、拷贝和丢弃策略。

<a id="PAT-014"></a>
### PAT-014 观察者／发布订阅（Observer / Pub-Sub）

- 意图：让事件发布者不知道具体订阅者。
- 适用：一对多通知，且订阅者集合确实会变化。
- 避免：用全局事件总线掩盖控制流和错误处理。
- 成本：调用顺序、线程上下文、背压和取消订阅更难追踪。

<a id="PAT-015"></a>
### PAT-015 主动对象（Active Object）

- 意图：把对象状态、消息队列和执行线程绑定为单一并发所有者。
- 适用：子系统需要串行处理异步请求并隔离并发。
- 避免：为每个小模块创建线程。
- 成本：线程栈、调度、消息延迟和关停协议。

<a id="PAT-016"></a>
### PAT-016 周期执行器（Cyclic Executive）

- 意图：按固定节拍依次运行一组有界任务。
- 适用：任务集合小、周期明确、执行时间可预算。
- 避免：任务阻塞或最坏执行时间未知。
- 成本：长任务会拖累整帧，需要抖动和超时监测。

<a id="PAT-017"></a>
### PAT-017 模板方法（Template Method）

- 意图：固定算法骨架，把少数步骤留给实现替换。
- 适用：多个流程共享严格顺序，仅局部动作不同。
- 避免：用回调网隐藏完整流程或制造脆弱继承层次。
- 成本：扩展点受骨架限制，调试需跨越间接调用。

<a id="PAT-018"></a>
### PAT-018 装饰器（Decorator）

- 意图：在不改变核心对象的前提下叠加日志、计量、重试或校验。
- 适用：横切行为可围绕稳定 Port 组合。
- 避免：重试等语义会改变安全行为却未在契约中声明。
- 成本：调用链加深，错误和时序预算需逐层计算。

<a id="PAT-019"></a>
### PAT-019 Fake／Null Object

- 意图：提供可控替身或安全空实现，降低测试和可选功能中的条件分支。
- 适用：主机测试、故障注入、可选外设。
- 避免：Null Object 静默掩盖本应报告的缺失依赖；避免用死循环或空返回冒充实现。
- 成本：替身也需遵守真实契约，并防止与真实行为漂移。

<a id="PAT-020"></a>
### PAT-020 监督者（Supervisor）

- 意图：集中监测子系统健康并执行分级恢复、降级或复位策略。
- 适用：存在看门狗、通信失联、任务超时和多级故障响应。
- 避免：监督者直接操纵所有模块内部状态。
- 成本：必须定义心跳、故障优先级、恢复次数和安全状态。

## 常见组合关系

```text
Port + Adapter + Dependency Injection + Composition Root
    = 可替换且可测试的环境边界

Registry
    = 保存/查找已存在对象
Factory
    = 决定并创建对象
Composition Root
    = 选择、连接并启动整个对象图
Resource Table
    = 声明要创建什么，不决定怎样使用
```

它们可以协作，但职责不能混合。注册表不应偷偷创建对象；工厂不应成为全局访问点；组合根不应承担运行期业务逻辑；配置表不应承载策略分支。

## 选择顺序

1. 先识别变化轴、所有权和执行上下文。
2. 再判断直接设计是否已足够。
3. 只有当模式能缩小变化扩散或提高验证能力时才采用。
4. 在架构决策中记录模式的退出条件和复杂度成本。
