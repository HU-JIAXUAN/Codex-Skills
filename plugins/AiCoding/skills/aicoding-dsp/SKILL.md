# 通用 DSP

默认使用简体中文。先解决数值、数据流与工程约束，再按实际目标补充硬件差异。不要从用户曾用过的处理器推断本次芯片、时钟、存储单位或库版本。

## Skill 类型

`reusable-domain-knowledge`、`team-expertise`。覆盖 DSP 处理器及具备信号处理能力的 MCU/SoC；不要求特定厂商、ISA、SDK、RTOS、数学库或分析软件。

## 使用边界

- 通用问题由本 skill 直接处理，不建立或切换到按具体芯片命名的 skill。目标明确后才按需读取系列参考；未提供目标时仍可完成算法、接口和验证方案。
- C 代码编写/修改结合 `aicoding-c99-standard-c`，代码评审结合 `aicoding-review`。保持已有编码、生成区、接口和构建边界。
- 本 skill 负责信号与数值实现；电机控制律、伺服环路综合及补偿参数由相应专项负责，涉及这些问题才补充调用。不要把一般 FFT 分析转成电机调参。
- 只处理当前目标需要的部分；用户限定只分析时不改文件，不顺带改外设、控制律、输出使能或工程发布状态。

## 工作方法

### 1. 建立最小输入契约

先从源码、构建配置、数据文件和已有记录读取，缺失且会改变决策时再询问：

- 信号：物理量/单位、输入范围、偏置、有效带宽、采样率和数据有效性。
- 执行：逐样本或分块、各阶段更新率、允许延迟、内存与栈预算。
- 数值：原始编码、缩放/标幺基值、整数/浮点格式、误差与溢出策略。
- 工程：当前算法和库、编译器/优化/ABI、构建目标与可用验证入口。纯算法任务无需补齐硬件清单。

采集率、算法调用率、输出更新率和遥测记录率分别命名。通信波特率、ISR 名称或图形软件设置不能单独证明数据采样率。

### 2. 先保持基线，再选择实现

复用已验证算法与项目已有库，先明确输入输出和状态行为。新建或替换实现时说明为何选择定点/浮点、逐样本/分块、标量/向量或加速器，以及精度、内存和延迟代价；不默认重写为汇编或迁移到协处理器。

定点写清总位数、分数位数、累加位宽、移位、舍入和每个饱和点；浮点写清实际精度、非有限值策略及允许误差。滤波器写清离散方程、系数顺序/符号、状态 owner、初始化/复位和采样率变化行为。

### 3. 还原数据与执行链

对流式或目标实现问题，追踪“物理采样/数据源 → 传输完成 → 缓冲发布 → 算法消费 → 结果发布/生效”。为相关事件记录时刻、序号、单位和 owner；区分旧样本、重复样本、缺失样本及结果未完成。

CPU、DMA、ISR、线程和加速器共享数据时，明确谁能读写、何时交接和何时可复用。`volatile` 不提供原子性、互斥、内存顺序或 cache 一致性。检查环形/双缓冲的回绕、满空、尾块和 overrun 策略。

### 4. 以证据驱动优化

先定位数值、计算、访存、传输、队列或日志瓶颈，再考虑库内核、块大小、数据布局、预计算、SIMD、RAM 放置或并行。每项优化同时记录前提、数值影响、总延迟和当前构建下的前后结果。

硬实时路径保持有界；不引入动态分配、阻塞格式化/输出、递归、无界重试或大栈临时数组。优化等级、fast-math、FMA、别名假设、对齐及迭代次数承诺都需要重新验证其适用前提。

## 验证与完成判断

按改动选择最小有效检查，不为低影响文本改动制造算法测试：

| 证据 | 适合证明什么 | 不据此声称什么 |
|---|---|---|
| 数学/高精度参考与边界向量 | 算法、数值格式、误差界、饱和及状态行为 | 目标 ABI、目标实时性 |
| 流式/分块回归与故障输入 | 分块一致性、复位、丢样/重复/尾块处理 | 硬件事件已经按期发生 |
| 目标构建、map 与反汇编 | 代码纳入目标、布局、库绑定和生成路径 | 板上结果正确、最坏时间达标 |
| 目标运行与时间记录 | 已覆盖工况下的结果、延迟、抖动与观测最大值 | 所有未覆盖工况的 WCET 上界 |

典型数值向量包括 impulse、step、DC、已知幅频正弦、满幅/负边界、长时间零输入、复位及饱和恢复；按问题选用。MATLAB、Python 或已有 C host harness 均可作为参考，不强制新增依赖。

采用项目真实命令；没有测量时实时结果记为 `NOT_MEASURED`，没有运行的检查记为 `NOT RUN`。目标不明、前提不足或文档冲突时写 `UNKNOWN`，不把某个系列的默认值补成事实。
