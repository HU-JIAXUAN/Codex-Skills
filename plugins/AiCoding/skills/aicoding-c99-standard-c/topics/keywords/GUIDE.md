# 关键字与语言机制的选择

## 触发语境

用户询问关键字含义、修饰符怎么用、某种写法能否替代另一种写法，或代码出现存储期、链接、限定符、类型与求值问题时使用。
先理解任务要解决的行为，再看词命中；注释、字符串、第三方代码中出现词语不自动触发重构。
本指南是 C99 总入口内部能力；入口已经加载时，在当前任务中按需补读相关指南，不反复转交入口。

## 必要输入

- 实际声明、定义、调用方和包含关系，以及用户期望改变的行为。
- 编译语言模式、目标编译器、ABI、链接脚本与实际告警。
- 对象由谁创建、读写、销毁，是否被 ISR、任务、DMA 或其他核访问。

## 按问题选择方法

| 问题或词组 | 先作出的判断 | 继续使用的方法 |
|---|---|---|
| `static`、`extern` | 区分作用域、存储期与链接；区分声明和定义 | [数据与寿命](../data/GUIDE.md) |
| `auto`、`register` | 自动存储期不表示必在硬件栈；`register` 不保证寄存器分配 | [数据与寿命](../data/GUIDE.md) |
| `const` | 区分对象只读视图、指向常量与常量指针，不据此推定存储位置 | [数据与寿命](../data/GUIDE.md) |
| `volatile` | 确认硬件副作用或异步变化，再单独设计一致性与同步 | [实时与并发](../realtime/GUIDE.md) |
| `restrict` | 证明本次访问关联的指针别名约束，调用方也须满足 | [安全与资源](../safety/GUIDE.md) |
| `inline` | 先确定函数职责和链接方案，再看生成代码与性能 | [表达式与控制流](../expressions/GUIDE.md) |
| `typedef`、`struct`、`union`、`enum` | 确定表示、有效成员、取值域和所有权，再决定类型形式 | [数据与寿命](../data/GUIDE.md) |
| `sizeof` | 区分对象、类型、数组和已退化指针；留意变长数组的求值规则 | [表达式与控制流](../expressions/GUIDE.md) |
| `signed`、`unsigned`、`char`、`short`、`int`、`long`、`float`、`double`、`_Bool`、`void` | 先确定范围、精度、单位和目标表示，再选类型；`void` 还需区分无结果、无参声明和无类型指针 | [数据与寿命](../data/GUIDE.md) |
| `_Complex`、`_Imaginary` | 先核对目标实现支持、数值表示和库接口，不假定所有嵌入式工具链提供同等能力 | [数据与寿命](../data/GUIDE.md)，数值算法按需结合 DSP Skill |
| `if`、`else`、`switch`、`case`、`default`、`for`、`while`、`do`、`break`、`continue`、`return`、`goto` | 由状态转移、退出条件与失败清理决定流程 | [表达式与控制流](../expressions/GUIDE.md) |

按以下顺序回答或修改，不把关键字解释停留在术语表：

1. 用一句话说明用户需要保持的行为，例如“仅本文件可见”或“DMA 完成前不得复用”。
2. 找到语言机制能保证的部分，并写清它不能保证的部分。
3. 沿声明、定义和真实调用链检查影响；仅修改完成该行为所必需的位置。
4. 涉及接口时补齐输入、输出、失败和上下文说明，再选择实际验证。

## 易混概念与限制

- `size_t`、`uint32_t` 是标准头提供的类型名，不是关键字；精确宽度类型取决于实现是否提供。
- `bool` 通常由 `<stdbool.h>` 提供；C99 关键字是 `_Bool`，不能把 C++ 的语言规则直接搬来。
- `#define`、`#include` 是预处理指令；宏展开、重复求值与条件编译问题交给表达式指南。
- `memcpy`、`strlen`、`malloc` 等是库函数；需要核对对象边界、终止、别名和失败契约。
- 不把加 `volatile`、强制类型转换或加 `inline` 当作通用修复；先证明缺陷原因。

## 实际验证

至少使用目标编译器核对声明、链接和诊断；存储位置看 map，性能看反汇编和相称测量。
语言边界用最小复现与标准语义核对；某次运行结果不能证明未定义行为具有可移植结果。
跨文件、异步访问和目标特性同时存在时，选择相关指南补齐验证，不能仅凭词法检查通过结束。
