# 注释体系

## 触发与输入

出现“写注释、文件说明、函数注释、关键代码、参数单位、字段含义、Doxygen、注释不一致”等任务时读取。输入必须包括真实代码、公共声明、相关调用者和当前项目注释约定；不能仅看函数名生成合同。

## 形成一致说明的流程

1. 确定文件用途、职责边界、资源/调用条件和对外能力；不将函数列表或目录名复述成文件头。
2. 对公共函数先明确输入、输出、返回、失败、寿命与上下文，再写调用者需要的合同。
3. 读取实现中的边界判定、计算/缩放、状态提交、资源回退、同步和硬件顺序，解释难以从语句直接看出的原因。
4. 字段区分配置、工作状态和结果，写实际用途、单位/范围与维护者；枚举逐项说明具体状态或错误。
5. 统一格式与术语后，反向检查说明是否被全部正常/失败路径满足；改代码时同步受影响说明。

## 分层职责

| 注释位置 | 说明什么 | 不应放什么 |
|---|---|---|
| 文件头 | 用途、职责边界、必要使用条件和关联接口 | 虚构作者/公司/认证，空历史表，逐函数列表 |
| 公共函数声明 | 参数、单位、可空性、输出/失败、返回、寿命与调用限制 | 未由实现保证的性能、安全或并发承诺 |
| 函数定义 | 当前关键实现意图，必要时说明步骤和取舍 | 与头文件复制后漂移的第二份接口合同 |
| 函数内段前 | 不显然的原因、边界和顺序 | 逐行翻译、自明赋值、只有“安全/原子”口号 |
| 字段/枚举 | 含义、单位/维护方、具体状态/错误 | 仅重复标识符或只注释整个类型 |

## 风格与限制

默认普通中文 `/* ... */`，多行内容缩进四空格，结束符独占一行，不加每行装饰星号或 Doxygen 标签。简单私有函数可一句用途说明；有参数、错误、寿命或上下文缺口时不能以“简单”为由省略。无参 void 不填一排无意义“无”。

需要分区时采用同一套一行星号标题，按职责命名。项目明确要求 Doxygen 时遵循项目格式，不能从旧示例自动恢复。稳定业务术语与单位在头文件、定义、注释和遥测中一致。

## 验收

机器可查配置支持的格式、非空说明和参数名覆盖；它不能证明文字正确。人工核对每个输出/错误路径、单位换算和并发前提。不要改规则或补空标签来消除诊断。
