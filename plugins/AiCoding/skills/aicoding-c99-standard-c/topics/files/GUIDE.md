# 文件与头文件

## 触发与输入

新建 `.c/.h`、拆文件、公共头、include、guard、`extern`、循环包含或文件编码成为当前任务时读取。先识别自研、生成、第三方归属，再读相邻文件、模板、实际字节/换行和构建接线。

## 新建或调整文件的流程

1. 从一个真实用例确定文件职责与允许依赖，判断是否已有稳定实现；模块化、平台适配或解耦按架构入口处理。
2. 决定哪些接口需要公开、哪些类型/状态仅在实现内使用，避免把私有实现或厂商头传给所有调用者。
3. 公共头自包含，只包含刚好需要的头，使用唯一 guard，声明与定义一致；没有公共能力时不机械造空头文件。
4. 实现包含自己的正式头验证一致性；内部声明集中、私有函数/状态 `static`，跨文件接口不靠手写重复 `extern`。
5. 按项目顺序组织 include、常量、类型、私有状态、内部声明和实现/对外函数，配同一套文件与函数说明。
6. 接入已有构建和必要的目标/host 验证，确认源文件、include 路径、宏与链接归属实际生效。

## 注意事项

- 头文件修改是对调用者的变化，要读实际使用者；不能只看它单独能编译。
- 不在公共头定义可变全局对象；共享常量、inline、宏和 C++ 互操作按项目及语言链接规则设计，不强制每个纯 C 头支持 C++。
- 先检查真实编码与 BOM/EOL，不因模板偏好批量转换；生成区和第三方保持实际风格，只做本次必要变化。
- 不复制无用标准头、平台万能头或空接口，不用文件数量证明职责合理。
- 不伪造作者、年份、版权、版本或公司字段。已有真实文件头要求继续保持。

## 验收与下一步

独立编译公共头，验证声明/定义、实际依赖和构建接线，检查编码及本次 diff。新增接口读[函数指南](../functions/GUIDE.md)，文件/函数说明读[注释指南](../comments/GUIDE.md)，整体格式读[命名排版](../style/GUIDE.md)。
