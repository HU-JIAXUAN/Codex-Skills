# 对象头与生命周期管理

用于需要统一管理异构设备/服务的工程。这里描述一种可选实现方案，保留职责、依赖、所有权与生命周期原则，不要求所有模块照搬布局或状态名称。

## 公共对象头表达什么

| 概念 | 作用与边界 |
|---|---|
| `name` | 对象身份与诊断，例如 `display0`、`sensor_svc`；明确名称唯一范围及字符串寿命，不能代替类型判定 |
| `type` | DEVICE/SERVICE 等对象大类；设备是硬件能力，服务组织可复用系统能力。具体服务类别或业务 API 另行表达 |
| `state` | 生命周期阶段，例如 CREATED、INITIALIZED、STARTED、STOPPED；与业务状态、数据有效性分别定义，选择一个迁移写入方 |
| `lifecycle` | 统一管理入口表，如 init/start/stop/deinit，以及确有需要的 process；签名、错误和完成语义一致，通常只读共享 |
| 可选 `magic` | 帮助诊断错误来源或明显的类型误用；不证明地址有效、对象存活或任意内存可读 |

`magic + type` 比单个标记能识别更多误用，但读取字段前对象本身就必须有效。不能让 `is_valid()` 接收任意地址后靠解引用证明安全；来源、注册与存储寿命先受控。DEVICE/SERVICE 只做粗分类，向具体 display 或 sensor 类型转换还要有真实对象/接口身份依据。

## 管理入口与业务行为分开

manager 可认识公共对象头，批量做登记、生命周期调用、状态汇总和必要诊断；不解释图像像素、IMU 坐标、服务阈值或私有 ctx，也不充当业务模块随时查找所有对象的全局入口。

统一生命周期表回答“对象如何投入与退出运行”；业务 `ops` 回答“对象提供什么能力”。显示提交画面、触摸取得事件、传感服务取得带质量的测量，应保留各自类型化接口。生命周期一致不要求业务行为统一成一组通用操作码。

manager 依赖公共管理契约，不因能取得对象地址就任意解释内部字段。字段表示成为独立问题时，可结合 `aicoding-data-model-design`，无需为完整流程总是切换 Skill。

## 启动与停止怎样组织

`register → init → start → process → stop → deinit` 可作为理解动作的例子。以下状态名和动作分解用于说明语义，实际对象可以合并、跳过或采用其他表示：

| 动作 | 设计重点 |
|---|---|
| register | 登记已构造对象，明确重复名称/对象、容量、存储寿命与登记 owner；登记本身通常不触发硬件或改变生命周期阶段 |
| init | 满足依赖、取得资源、建立初态；成功后才提交 INITIALIZED，失败清理本次已取得资源 |
| start | 开启采集/执行/调度；成功后才提交 STARTED，失败保留可恢复状态并清理部分启动资源 |
| process | 通常是 STARTED 期间重复或事件触发的有界动作，不是新阶段；中断/DMA/被动对象可以没有它，不强制轮询或每对象一线程 |
| stop | 明确停止期间还接受哪些请求，如何取消或排空在途工作，以及何时才算完成；状态与同步/异步完成语义一致 |
| deinit | 确认使用者及在途回调均已退出后释放/复原资源；返回 CREATED 或项目定义的结束状态，不把反初始化等同于释放静态存储 |

重复 init/start/stop、非法顺序、可选入口缺失、重新启动与失败恢复怎样处理，由对象契约明确，不默认静默成功。manager 根据返回结果提交状态或由对象内部提交，选择一种单一写入方式；不要两边重复维护生命周期副本。

先初始化并启动依赖提供者，再处理使用者；停止与释放通常按依赖反向进行。只回退本轮已成功完成的动作，保留资源共享 owner，不误释放仍被其他对象使用的提供者。停止后仍能到达的 DMA/回调必须在对象存储复用前取消、排空或隔离，单改 state 无法保证这一点。

例如传感器设备依赖总线，测量服务依赖传感器：启动代码绑定实例并按依赖安排生命周期，App 使用测量能力。可以选静态对象表和普通函数，也可以复用工程已有管理机制；由对象集合与变化需求决定。

## C 首成员嵌入的适用条件

若实现依赖“具体对象地址与公共头地址可按首成员规则转换”，将实际公共对象头作为第一个成员，保持正确对齐，并用 `offsetof` 的编译期检查维护这一局部布局约定。通用代码也可以显式持有公共头指针，不必所有工程都使用首成员模拟继承。

转回具体类型时，指针必须确实来自那个仍存活的完整对象；相同前缀、相同 magic、相同 DEVICE 大类都不能独自证明合法。C99 工程使用其工具链支持的断言形式，不照搬 C11 `_Static_assert` 要求。

语言依据见 [WG14 N1570 §6.7.2.1 第15段](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：这里只借用结构体与首成员关系，没有把 C11 新语法变成 C99 要求。[Zephyr 官方设备模型](https://docs.zephyrproject.org/latest/kernel/drivers/index.html)也展示只读配置、每实例运行数据与分类 API 的分离，可借鉴其思想，不复制整个框架或其具体调度规则。
